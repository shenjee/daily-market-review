- 文档类型：产品需求

- 所属项目：daily-market-review
- 指标口径：[资本市场复盘指标说明与统计口径](../references/资本市场复盘指标说明与统计口径.md)
- 字段与保存语义：[数据字段与口径](../references/数据字段与口径.md)

本文档规定产品目标、用户场景、功能范围、非目标和用户可观察的验收结果。表结构、模块位置、事务和 migration 见数据库设计。Agent 运行时的取数步骤见 `references/Skill行为说明.md`。

## 1. 产品目标

每日市场复盘用于记录、修正和展示指定已收盘交易日的资本市场数据，形成口径稳定的日度复盘账本。

数据库是长期积累的数据资产，不只服务于 Skill，也必须能够直接支持 Stock Pilot 应用。

本文档只规定 `daily-market-review`；其他 Skill 的范围与触发词不在本文档处理。

## 2. 用户场景

- 收盘后整理当日总体复盘，或从图片、链接、文字中提取并保存。
- 只补齐某一类字段，例如「补齐两融」「补齐三大指数」。
- 保存或修订涨跌停事件、连板高度和每日梯队扩展信息。
- 查看已保存的总体复盘或每日梯队，不联网补数。
- 发现错误后按字段或单股事件修订；数据可能录错，用户查看时再改。

## 3. 职责边界

| 层 | 职责 |
| --- | --- |
| 数据层 | 表结构、SQLite 持久化、读取侧统计，以及交易日历和最小行情能力 |
| JSON CLI | 写入路径执行业务校验后再落库 |
| Skill | 理解用户请求，取得数据，调用 CLI 写入；读取后格式化展示 |

产品约束：

- Skill 只通过 CLI 读写，不直接操作数据库。
- CLI 将调用方提交的数据视为待保存内容，按原样存取，不判断市场事实是否正确。
- 数据可能录错；修订由用户发起。数据库不承担事实核验。
- 腾讯指数 K 线里的 `amount` 不等同于交易所全市场成交额，不作为市场成交额自动写入。

## 4. 功能范围

### 4.1 总体复盘

指定交易日的总体复盘包含：

| 类别 | 指标 |
| --- | --- |
| 涨跌停 | 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率 |
| 市场宽度 | 回头波数、中位数涨跌幅、上涨家数、下跌家数、涨跌停比 |
| 连板 | 首板数、连板数、连板率、最高板、最高板代表、按实际高度动态分组的数量 |
| 两融 | 上海、深圳、北京融资余额及合计 |
| 指数 | 上证、深证成指、创业板指的点位、涨跌点数和涨跌幅 |
| 成交额 | 上海、深圳、创业板、北京及合计；创业板单独展示但已包含在深圳成交额中 |
| 市场规模与估值 | 总市值、流通市值、上海 PE、深圳 PE、创业板 PE、全市场 PE |
| 平均股价 | 平均股价 |

指标及展示统一使用成交额。系统只处理收盘后的日度数据。

涨跌停基础数量、炸板率、涨跌停比、连板汇总、融资余额合计、成交额合计和指数涨跌均由已保存事件或原子字段在读取后统计，用户不能把汇总值当成独立字段入库。

### 4.2 每日涨跌停事件与梯队

每日涨跌停事件按交易日、股票和方向保存，并记录收盘是否仍处于对应涨跌停价格。数据库不判断名单是否完整。

每日梯队不是另一份股票名单。它读取已保存的有效涨停事件，按实际连板高度从高到低动态分组；首板属于梯队。涨停炸板、打开跌停和收盘跌停不属于梯队，作为独立名单展示。

每条事件可附带可空梯队扩展：所属板块、涨停原因（仅涨停方向）、个股行情快照、是否龙头和备注。竞价占比和开盘涨幅读取后计算，不入库。

### 4.3 情绪周期图

情绪周期图是跨交易日的展示视图，不单独保存重复聚合。当前版本不把它作为可写入功能交付。

## 5. 出数承诺

每个指标属于以下三类之一。

### 5.1 固定自动获取

仅承诺三只指数的当日收盘与前收盘：上证 `000001`、深证成指 `399001`、创业板指 `399006`。请求范围包含这些指数字段且未指定来源时必须尝试；失败不覆盖原值，不用其他日期顶替。

### 5.2 读取后统计

有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率、涨跌停比、首板与连板汇总、连板率、融资余额合计、成交额合计、三只指数涨跌点数和涨跌幅，以及每日梯队视图，均不入库。

### 5.3 尽力获取或由用户提供

涨跌停事件、市场宽度、两融、成交额、市值、PE、平均股价和每日梯队扩展信息不承诺固定自动数据源。失败则一次性列出，不得猜测或用前一日数据顶替。

## 6. 非目标

- 不处理午间数据、开盘情绪和情绪周期阶段判断。
- 不承诺腾讯、东方财富或其他固定 provider 的可用性（三只指数日 K 除外）。
- 不保存分时序列、日 K 序列、走势图图片、网页链接、截图或行情接口原始响应。
- 不提供买卖建议。
- 不把有效涨停数、最高板、连板数等派生汇总值作为独立字段保存。

## 7. 用户可观察的验收标准

1. 未指定日期时，查看和写入都使用最近一个已收盘交易日。用户说「今天」：查看在盘前或非交易日回退最近已收盘交易日，收盘后使用当日；写入在交易日收盘前必须拒绝，不得改写到上一交易日；若「今天」不是交易日，不落库并提示最近交易日。
2. 用户显式指定非交易日：不落库，并提示最近交易日；显式指定尚未收盘的当日：拒绝生成正式记录。
3. 自动获取仅承诺三只指数日 K；成功则写入收盘与前收盘，失败不覆盖原值。
4. 写入只处理本次请求范围内取得或由用户提供的数据；指定来源不得把未点名字段用其他来源悄悄补上。
5. 涨跌停基础数量及全部连板、比值、合计类指标由读取后统计得到，不能独立入库。
6. 用户要求显示时只读取和格式化已保存数据，不自动取数、追问或修改数据库。
7. 总体复盘按八个类别以简单表格展示；原子字段为 `null` 时留空，已确认的 `0` 必须显示为 `0`。
8. 没有总体复盘行但仍有涨跌停事件时，展示事件及其派生指标；两类都不存在时显示「无复盘数据」。不得把「没有记录」显示成指标为 `0`，也不得把已保存的 `0` 当成缺失。
9. 同一交易日重复执行不产生重复总体复盘，并遵守字段级 patch。
10. 事件扩展只能关联已保存事件；只读梯队请求不联网补数。
11. 默认用户数据位于 `~/.marketreview/market_review.sqlite3`；来源和采集方式不入库。
