# 每日市场复盘 Skill PRD

- 文档类型：产品需求
- Skill 名称：`daily-market-review`
- 所属项目：daily-market-review

## 1. 文档目的与产品定义

本文档说明为什么做每日市场复盘、给谁用、核心路径如何完成，以及当前版本承诺什么、不承诺什么。字段、单位、patch、指标公式和表结构见文末相关规格；本文不重复那些细节。

**一句话定义：** 每日市场复盘是指定已收盘交易日的资本市场日度账本——记录、修订和展示口径稳定的复盘数据，并可被下游应用长期读取。

本文档只规定 `daily-market-review`；其他 Skill 的范围与触发词不在本文档处理。当前版本的主要交互入口是自然语言对话；保存的数据是可长期积累的数据资产，可被 Stock Pilot 等应用读取。

## 2. 背景与要解决的问题

收盘后复盘数据常见于截图、临时表格和聊天记录。这些形态有结构性缺陷：

- **截图只能看，不能稳定修订、累计和按日查询。**
- **临时表格口径容易漂移**，派生值（有效涨停数、连板率等）常与原始事件混在一起，日后难以核对。
- **聊天记录缺少日期、字段和事件层面的可追溯结构**，同一天的补录和纠错难以落到同一份记录上。
- **Stock Pilot 等应用无法可靠消费**上述非结构化资料。
- **自动数据源并不总是完整可靠**，产品必须允许部分录入、以后补齐、用户纠错，而不是要求一次取全或静默用旧值顶替。

因此产品定位是**日度账本**，而不是行情终端或又一份采集脚本：先固定「一天一份、可补可改、派生可读」的账本合同，再谈如何取数。

## 3. 用户与数据消费者

| 角色 | 关系 |
| --- | --- |
| 人类用户 | 整理、补录、修订和查看复盘；对录入内容负责确认与纠错 |
| 下游消费者 | 以 Stock Pilot 为代表，读取稳定落库的数据；不是当前 Skill 的对话用户 |

## 4. 核心使用场景

每个场景按「触发 → 用户提供什么 → 系统做什么 → 缺失时怎么办 → 完成结果」描述。**允许部分落库，但必须完整报告结果**：请求范围内该尝试的都尝试了、成功写入的与未写入的都已说明、范围外未擅动，即视为该请求处理完成；未取得或校验失败不等于数据已保存成功。

### 4.1 收盘后完成一次总体复盘

- **触发：** 用户要求整理某已收盘交易日（或「今天」且已收盘）的总体复盘。
- **用户提供：** 可不指定来源；也可附带截图、链接或口头补数。
- **系统做什么：** 确定已收盘交易日与请求范围（完整复盘）；对范围内未指定来源的字段尽力取得；范围内自动承诺的指数必须尝试；通过格式与业务校验后写入；按类别展示已保存结果。
- **缺失时：** 一次性列出范围内未取得项；用户可跳过。新记录中跳过的原子字段为空；已有记录中的对应字段保持原值。两者都不得用 `0` 或前一日数据代替。
- **完成结果：** 当日总体复盘行已建立或已按 patch 更新；范围内已取得字段已保存；未取得项已说明；派生指标由已保存数据读出。

### 4.2 从截图、链接或文字提取并保存

- **触发：** 用户给出图片、网页或文字，要求提取复盘或涨跌停相关数据并保存。
- **用户提供：** 来源材料，以及可选的日期与范围限定。
- **系统做什么：** 先定范围（完整复盘、事件、梯队扩展，或点名字段）；只用来源中能明确识别且落在范围内的内容构造写入；日期、单位或身份无法确认的字段不写。
- **缺失时：** 看不清、日期不一致、单位不明或多来源冲突的项不入库，并一次性说明；不另找来源悄悄填空，除非用户同时要求扩大范围或自动补齐。
- **完成结果：** 来源能支持且校验通过的字段已写入；其余保持原值或为空；用户清楚哪些未写入。

### 4.3 只补充局部数据

- **触发：** 例如「补齐两融」「补齐三大指数」「把上涨家数改成 3210」。
- **用户提供：** 点名的类别或字段，以及可选来源。
- **系统做什么：** 范围仅限点名项；范围内未指定来源则尽力获取（指数在自动承诺内则必须尝试）；范围外不取、不写。
- **缺失时：** 只报告点名范围内的未取得项。
- **完成结果：** 成功取得并校验通过的数据已保存；未取得或校验失败的数据已明确说明；其余字段未处理。这是局部请求的处理完成，不等于范围内每一项都已落库。

### 4.4 发现错误后局部修订

- **触发：** 查看后发现某字段、某只股票事件或梯队扩展有误。
- **用户提供：** 正确值、应清空的字段，或应增删改的事件 / 明细。
- **系统做什么：** 按字段级 patch 或事件身份更新；方向变更走原子替换；不重建无关数据。
- **缺失时：** 用户未点名的字段与事件保持原样。
- **完成结果：** 错误项已更正；同日其他已确认数据仍在；再次查看反映修订结果。

### 4.5 只查看总体复盘或每日梯队

- **触发：** 用户要求查看某日复盘、涨跌停或每日梯队。
- **用户提供：** 日期或「今天」等相对说法；可选过滤（如某高度、某股票）。
- **系统做什么：** 只读取已保存数据并格式化展示；不联网取数、不追问缺失、不修改数据库。
- **缺失时：** 原子字段为空则留空；无复盘行且无事件则显示「无复盘数据」；有事件无复盘行仍展示事件及派生指标。已确认的 `0` 显示为 `0`，与缺失区分。
- **完成结果：** 用户看到与库内一致的视图；数据库未被改动。

## 5. 产品原则

1. **日度账本，不是实时行情终端。** 只处理已收盘交易日的日度数据；不服务盘中盯盘或分钟级刷新。
2. **原子事实入库，派生结果读取时计算。** 有效涨停数、炸板率、连板汇总、合计、涨跌幅、梯队分组等不作为独立入库字段。
3. **允许缺失、允许修订，以用户确认的数据为准。** 系统校验格式、交易日、身份键、单位与逻辑约束；不替用户裁决外部行情是否真实、名单是否齐全或龙头判断是否正确。录错可以以后改。
4. **严格遵守请求范围，不隐式补全。** 指定来源或点名字段时，不把范围外或未点名指标用其他来源悄悄补上。
5. **查看是只读行为。** 不触发联网补数、追问或写入。
6. **分流默认要写清；读库失败不改写范围。** 先判操作意图再判字段范围：未限定字段的「统计 / 汇总」默认完整复盘写入；点名统计只处理点名范围。库不可用时报告数据库状态未知，不推断库内缺项。
7. **采集状态与数据库状态分开报告。** 二者可同时成立；须区分未采集、部分采集与已核验零事件；事件派生指标按库内记录统计展示，不得暗示全市场已核验。部分完成时不得宣称整单完成；成功核验写入的项不列入未完成。

补充：腾讯指数 K 线中的成交额字段不等同于交易所全市场成交额，不得当作市场成交额自动写入。

## 6. 当前版本范围

系统只处理收盘后的日度数据。指标及展示统一使用成交额。

### 6.1 总体复盘

| 类别 | 指标 |
| --- | --- |
| 涨跌停 | 有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率 |
| 市场宽度 | 回头波数、中位数涨跌幅、上涨家数、下跌家数、涨跌停比 |
| 连板 | 首板数、连板数、连板率、最高板、最高板代表、按实际高度动态分组的数量 |
| 两融 | 上海、深圳、北京融资余额及合计 |
| 指数 | 上证、深证成指、创业板指的点位、涨跌点数和涨跌幅 |
| 成交额 | 上海、深圳、创业板、北京及合计；创业板单独展示但已包含在深圳成交额中 |
| 市场规模与估值 | 总市值、流通市值、上海 PE、深圳 PE、创业板 PE、全市场 PE |
| 平均股价 | 平均股价 |

涨跌停基础数量、炸板率、涨跌停比、连板汇总、融资余额合计、成交额合计和指数涨跌均由已保存事件或原子字段在读取后统计，用户不能把汇总值当成独立字段入库。

### 6.2 每日涨跌停事件与梯队

每日涨跌停事件按交易日、股票和方向保存，并记录收盘是否仍处于对应涨跌停价格。系统不声明某日名单完整。

每日梯队不是另一份股票名单。它读取已保存的有效涨停事件，按实际连板高度从高到低动态分组；首板属于梯队。涨停炸板、打开跌停和收盘跌停不属于梯队，作为独立名单展示。

每条事件可附带可空梯队扩展：所属板块、涨停原因（仅涨停方向）、个股行情快照、是否龙头和备注。竞价占比和开盘涨幅读取后计算，不入库。

## 7. 出数与缺失处理承诺

每个指标属于以下三类之一。

### 7.1 固定自动获取

仅承诺三只指数的当日收盘与前收盘：上证 `000001`、深证成指 `399001`、创业板指 `399006`。请求范围包含这些指数字段且未指定来源时必须尝试；失败不覆盖原值，不用其他日期顶替。

### 7.2 读取后统计

有效涨停、20% 涨停、打开跌停、收盘跌停、涨停炸板、炸板率、涨跌停比、首板与连板汇总、连板率、融资余额合计、成交额合计、三只指数涨跌点数和涨跌幅，以及每日梯队视图，均不入库。

### 7.3 尽力获取或由用户提供

两融默认从同花顺采集，用户指定来源时优先采用该来源，按实际单位换算；日期与异常处理见 Skill 采集说明。涨跌停事件、市场宽度、成交额、市值、PE、平均股价和每日梯队扩展信息不承诺固定自动数据源。失败则一次性列出，不得猜测或用前一日数据顶替。

## 8. 非目标

- 不处理午间数据、开盘情绪和情绪周期阶段判断。
- 不承诺腾讯、东方财富或其他固定 provider 的可用性（三只指数日 K 除外）。
- 不保存分时序列、日 K 序列、走势图图片、网页链接、截图或行情接口原始响应。
- 不提供买卖建议。
- 不把有效涨停数、最高板、连板数等派生汇总值作为独立字段保存。

## 10. 用户可观察的验收标准

1. 未指定日期时，查看和写入都使用最近一个已收盘交易日；单独补齐融资余额按来源最新交易日期保存，完整复盘中的融资余额须匹配目标复盘日。用户说「今天」：查看在盘前或非交易日回退最近已收盘交易日，收盘后使用当日；写入在交易日收盘前必须拒绝，不得改写到上一交易日；若「今天」不是交易日，不落库并提示最近交易日。
2. 用户显式指定非交易日：不落库，并提示最近交易日；显式指定尚未收盘的当日：拒绝生成正式记录。
3. 自动获取仅承诺三只指数日 K；成功则写入收盘与前收盘，失败不覆盖原值。
4. 写入只处理本次请求范围内取得或由用户提供的数据；指定来源不得把未点名字段用其他来源悄悄补上。局部请求在点名范围内尝试完毕、成功写入与失败项均已说明、范围外未擅动时，视为该请求处理完成；未取得或校验失败不计入已保存成功。
5. 涨跌停基础数量及全部连板、比值、合计类指标由读取后统计得到，不能独立入库。
6. 用户要求显示时只读取和格式化已保存数据，不自动取数、追问或修改数据库。
7. 总体复盘按八个类别以简单表格展示；原子字段为 `null` 时留空，已确认的 `0` 必须显示为 `0`。
8. 没有总体复盘行但仍有涨跌停事件时，展示事件及其派生指标；两类都不存在时显示「无复盘数据」。不得把「没有记录」显示成指标为 `0`，也不得把已保存的 `0` 当成缺失。
9. 同一交易日重复执行不产生重复总体复盘，并遵守字段级 patch。
10. 事件扩展只能关联已保存事件；只读梯队请求不联网补数。
11. 默认用户数据位于 `~/.marketreview/market_review.sqlite3`；来源和采集方式不入库。
