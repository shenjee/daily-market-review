# V2 每日梯队开发实现

## 1. 文档目的

本文档是 `daily-market-review` V2「每日梯队」的**历史实现规格**，当时的表结构、CLI 和测试清单已落地。现行产品合同以 [PRD](PRD.md) 和 [数据库设计](数据库设计.md) 为准；运行时口径以 `references/` 下字段合同、行为说明和指标附录为准。与本文冲突时以现行文档和代码为准。

不要再根据本文去「补做 V2」或把 README / SKILL.md 改回未实现状态。

## 2. 已确认的产品决策

1. 现有 `daily_price_limit_event` 是梯队的唯一股票名单来源，不复制每日名单。
2. 首板属于每日梯队；梯队包含所有 `direction=up and closed_at_limit=true and streak_height>=1` 的事件。
3. 梯队按实际 `streak_height` 从高到低动态分组，不创建固定板高字段或日度聚合表。
4. 涨停炸板、打开跌停和收盘跌停不进入梯队，作为独立名单返回。
5. V2 数据不承诺固定来源。Skill 可使用腾讯、东方财富、用户文字、截图、网页抓取或 Agent 可用来源尽力取得。
6. 未取得的数据留空，不猜测，不用其他日期的数据替代；数据库不保存数据来源、URL、截图或采集方式。
7. `sectors` 和 `limit_up_reasons` 都是有序、多值字段。
8. V2 首版只保存收盘后个股快照，不保存分时序列、日 K 序列、走势图图片或行情原始响应。

## 3. 不变的 V1 合同

- Skill 只能通过 `scripts/cli.py` 读写，不能直接 import package 或操作 SQLite。
- 事件身份仍为 `(trade_date, market, code, direction)`。
- `streak_height` 仍由调用方最终提交；V2 不改变连板高度计算规则。
- 总体复盘的 `summary` 字段和现有 CLI 命令保持向后兼容。
- `save-events` 的现有输入继续有效。
- 空事件列表仍是 no-op，不代表完整快照或清空。
- 删除总体复盘不删除同日事件或事件扩展数据。

## 4. 数据模型

### 4.1 事件扩展表

新增 `daily_price_limit_event_detail`，与事件一对一：

```sql
CREATE TABLE IF NOT EXISTS daily_price_limit_event_detail (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    previous_turnover_amount REAL,
    auction_amount REAL,
    previous_close REAL,
    open_price REAL,
    turnover_amount REAL,
    turnover_rate REAL,
    is_leader INTEGER,
    note TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;
```

约束：

- 金额统一按元保存。
- `previous_close`、`open_price` 必须大于 `0`；金额和 `turnover_rate` 必须大于等于 `0`。
- 百分比统一保存为小数，例如换手率 `12.5%` 保存为 `0.125`。
- `is_leader` 为三态：`1` 是、`0` 否、`NULL` 未判断。
- `note` 保存普通文本；空字符串应在输入校验阶段规范为 `NULL`，不保存空白占位。

### 4.2 板块多值表

```sql
CREATE TABLE IF NOT EXISTS daily_price_limit_event_sector (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    position INTEGER NOT NULL,
    value TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction, position),
    UNIQUE (trade_date, market, code, direction, value),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;
```

### 4.3 涨停原因多值表

```sql
CREATE TABLE IF NOT EXISTS daily_price_limit_event_reason (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    position INTEGER NOT NULL,
    value TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction, position),
    UNIQUE (trade_date, market, code, direction, value),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;
```

两个多值表都保留调用方提交顺序。`position` 从 `0` 开始连续编号，不把外部来源的序号直接入库。

输入时对每个值执行首尾空白清理，拒绝空字符串；清理后完全相同的值只保留第一次出现的位置。不自动合并近义词。

### 4.4 现有数据库兼容

V2 只新增表，不修改或重建 V1 表。`init_db` 对已有数据库执行 `CREATE TABLE IF NOT EXISTS` 即可完成兼容升级，不得删除、复制或重写已有用户数据。

连接初始化必须执行 `PRAGMA journal_mode=WAL` 和 `PRAGMA foreign_keys=ON`，并读取实际值确认。文件数据库的 `journal_mode` 必须为 `wal`；内存数据库允许 `memory`。SQLite 在活动事务中不会启用这两项 PRAGMA；若连接已在事务中且未能达到要求，必须拒绝初始化，不得继续建表或写入。测试必须覆盖新建数据库、仅含 V1 表的已有数据库、活动事务中外键未开启的连接，以及文件型活动事务连接未能进入 WAL 的路径。

## 5. Python 公共数据结构

在 `scripts/marketreview/schema.py` 增加：

- `PriceLimitEventDetailPatch`：写入 patch，所有业务字段可选，并能区分“未提交”和“显式 null”。不要使用普通 dataclass 默认 `None` 混淆这两个状态；可使用字段集合加 payload 的结构。
- `PriceLimitEventDetailRecord`：持久化后的完整可空字段。
- `LadderStock`：事件核心字段、扩展字段和派生字段的组合读取模型。
- `LadderGroup`：`streak_height`、`count`、`stocks`。

多值字段使用 `list[str]`。公共返回值不得暴露 SQLite 的 `0/1`，应转换为 Python `bool | None`。

## 6. 写入接口

### 6.1 新增 CLI 命令

新增命令：

```bash
python3 scripts/cli.py save-event-details --date 2026-08-21 --input -
```

输入：

```json
{
  "details": [
    {
      "market": "sh",
      "code": "600519",
      "direction": "up",
      "sectors": ["白酒", "消费"],
      "limit_up_reasons": ["业绩增长", "消费复苏"],
      "previous_turnover_amount": 8450000000,
      "auction_amount": 326000000,
      "previous_close": 1520.5,
      "open_price": 1568.0,
      "turnover_amount": 9630000000,
      "turnover_rate": 0.0125,
      "is_leader": true,
      "note": "用户确认的主线龙头"
    }
  ]
}
```

身份字段 `market`、`code`、`direction` 必填，其他字段使用 patch 语义：

| 输入 | 行为 |
| --- | --- |
| 未出现字段 | 保留原值 |
| 标量具体值，包括 `0` 和 `false` | 更新 |
| 标量显式 `null` | 清空 |
| 多值字段未出现 | 保留原列表 |
| 多值字段为 `[]` | 清空列表 |
| 多值字段为非空数组 | 整体替换列表 |

写入前必须确认父事件存在；不存在时整批失败，不得偷偷创建不完整事件。批量 patch 必须在一个事务中完成，任何一条失败时整批回滚。

空 `details` 数组是 no-op，不代表清空当日扩展数据。

### 6.2 repository 能力

增加：

- `save_price_limit_event_details(trade_date, details)`
- `get_price_limit_event_details(trade_date)`
- `list_price_limit_event_details(start_date, end_date)`

保存方法只做结构性规范化和持久化；市场事实、来源可信度和龙头判断由 Skill 与用户负责。

### 6.3 删除与方向替换

- 删除单条事件或整日事件时，依赖外键级联删除对应 detail、sector 和 reason。
- `replace_price_limit_event_direction` 是身份修订，不应静默丢失扩展数据。实现时应在同一事务内确认旧身份存在、目标身份不存在，再读取旧扩展数据、替换核心事件，并把扩展数据迁移到新方向。旧身份不存在或目标身份已存在时整笔失败，不得退化成插入或覆盖。
- 明细标量和 `sectors` 随身份迁移。`limit_up_reasons` 只适用于 `direction=up`：由 `up` 改为 `down` 时不迁移该字段，这是字段语义失效后的清理，不是静默丢弃通用标签。其余人工标签若新方向不再适合，保留现有值，由用户显式清空。

## 7. 读取与梯队视图

### 7.1 `get` 返回兼容扩展

现有 `get` 返回结构保持不变，并新增顶层字段 `ladder`：

```json
{
  "trade_date": "2026-08-21",
  "review": {},
  "events": [],
  "summary": {},
  "missing_fields": [],
  "ladder": {
    "groups": [],
    "broken_limit_up": [],
    "opened_limit_down": [],
    "closed_limit_down": []
  }
}
```

不要改变现有 `events` 对象的字段集合，避免破坏依赖 V1 输出的调用方。

### 7.2 梯队分组

`groups` 只包含：

```text
direction=up
and closed_at_limit=true
and streak_height>=1
```

规则：

- 首板以 `streak_height=1` 进入梯队。
- 分组按高度降序。
- 每组返回实际高度、股票数量和股票明细。
- 同一高度内按 `market, code` 升序稳定排序；`is_leader` 只显示标签，不改变顺序。
- 不限制最高高度，不生成 `11板+` 存储字段。
- 不因 detail 缺失而排除股票；缺失扩展字段返回 `null` 或空列表。

辅助名单：

- `broken_limit_up`：`direction=up and closed_at_limit=false`
- `opened_limit_down`：`direction=down and closed_at_limit=false`
- `closed_limit_down`：`direction=down and closed_at_limit=true`

### 7.3 派生字段

每只股票读取时计算：

```text
auction_ratio = auction_amount / previous_turnover_amount
open_change = open_price / previous_close - 1
```

- 任一输入为 `null` 时结果为 `null`。
- 分母为 `0` 时结果为 `null`。
- 不把派生结果写入数据库。
- package 返回原始小数，不提前转成带 `%` 的字符串；展示层负责格式化。

建议新增 `scripts/marketreview/ladder.py`，集中实现事件与扩展数据组合、分组和派生计算，避免把逻辑塞进 CLI。

## 8. Skill 数据获取与展示

### 8.1 获取规则

V2 不新增固定自动获取承诺。Skill 可按可用性选择腾讯、东方财富、用户文字、截图、网页抓取或其他 Agent 来源。

- 用户指定来源时，只使用该来源处理点名范围。
- 用户未指定来源时，Skill 可尽力寻找来源。
- 日期、单位或股票身份无法确认时不写入。
- 多来源冲突时不猜测；优先遵从用户明确指定来源，否则列出冲突项。
- 只写入成功取得且通过校验的字段；失败字段一次性列出。

### 8.2 展示规则

- 标题包含交易日期。
- 梯队按最高板至首板展示。
- 每组显示股票代码、名称、板块、涨停原因、竞价占比、开盘涨幅、当日成交额、换手率、龙头标记和备注。
- 缺失标量留空；缺失多值字段显示为空，不使用占位词。
- 板块和涨停原因按保存顺序以 ` / ` 连接。
- 金额按阅读需要换算为万元或亿元；比例转为百分数并保留两位小数。
- 炸板、打开跌停和收盘跌停名单在梯队之后独立展示。
- 只读请求不联网补数、不追问、不修改数据库。

## 10. 测试与验收

### 10.1 schema 与 repository

- V1 既有数据库初始化后新增三张表，原数据不变。
- detail 标量字段新增、更新、显式清空和未提交保留。
- 列表字段整体替换、空列表清空、未提交保留、去重和顺序保存。
- 父事件不存在时拒绝写入。
- 批量写入中一条失败时整批回滚。
- 删除事件级联删除三张扩展表的数据。
- 方向替换后扩展数据迁移到新身份。
- `false`、`0` 与 `null` 不混淆。

### 10.2 梯队统计

- 首板进入高度 `1` 分组。
- 二板及以上按实际高度降序分组。
- 炸板不进入梯队，进入 `broken_limit_up`。
- 打开跌停与收盘跌停进入各自名单。
- 同高度按 `market, code` 稳定排序。
- detail 缺失的有效涨停仍进入梯队。
- 竞价占比和开盘涨幅计算正确；缺失值或零分母返回 `null`。
- 多板高度不受 `11` 限制。

### 10.3 CLI 与兼容性

- `save-event-details` 支持对象包装数组格式。
- 错误仍使用统一 `{ok, data, error}` 结构。
- `get` 的 V1 字段与内容保持兼容，只新增 `ladder`。
- 现有全部单元测试继续通过。
- 新增黄金 fixture，至少包含首板、连板、龙头、多板块、多涨停原因、缺失 detail、炸板和跌停。
