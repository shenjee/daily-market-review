# 数据库设计

本文档覆盖持久化架构、表结构、兼容策略和技术验收。产品范围见 [PRD](PRD.md)。运行时字段名、单位与 patch 语义以 [数据字段与口径](../references/数据字段与口径.md) 为准；指标公式以 [指标说明](../references/资本市场复盘指标说明与统计口径.md) 为准。

V2「每日梯队」表结构已落地。当时的实现清单见 [V2每日梯队开发实现](V2每日梯队开发实现.md)，该文是历史规格，与本文冲突时以本文和现行代码为准。

## 1. 分层

| 位置 | 职责 |
| --- | --- |
| `scripts/marketreview/sqlite_schema.py` | 建表、连接 PRAGMA、schema 初始化 |
| `scripts/marketreview/repository.py` | 结构性持久化；不复核行情事实 |
| `scripts/marketreview/ladder.py` | 组合事件与明细、分组、派生竞价占比和开盘涨幅 |
| `scripts/marketreview/summary.py` | 读取侧统计 |
| `scripts/marketreview/calendar.py` | 内置交易日历，数据在 `assets/trading_calendar.json` |
| `scripts/marketreview/sources/tencent.py` | 三只指数的最小日 K |
| `scripts/marketreview/business_validation.py` | CLI 写入路径的交易日、市场、代码、方向和涨跌幅限制校验 |
| `scripts/cli.py` | JSON CLI 入口 |

约束：

- 公共字段使用 `snake_case`。
- 数据库使用 SQLite STRICT 表。
- Skill 与外部应用都通过 `scripts/cli.py` 读写，不直接 import 包操作 SQLite（测试除外）。
- CLI 不提供复杂的外部采集编排接口。

## 2. 数据库定位

默认路径：

```text
~/.marketreview/market_review.sqlite3
```

路径优先级：`CLI --db` > `MARKETREVIEW_HOME/market_review.sqlite3` > 默认路径。

- Skill 安装目录不保存用户数据。
- 多个 Agent 可共享同一份用户数据。
- 打开已有数据库时执行 `CREATE TABLE IF NOT EXISTS` 补齐新表，不改写已有用户数据。
- 涉及已有列变化时必须使用显式 schema migration，并保留已有数据。

连接初始化必须执行 `PRAGMA journal_mode=WAL`、`PRAGMA busy_timeout=5000` 和 `PRAGMA foreign_keys=ON`，并读取实际值确认。文件数据库的 `journal_mode` 必须为 `wal`；内存数据库允许 `memory`。若连接已在事务中导致 PRAGMA 无效，必须拒绝初始化。

## 3. 核心数据表

| 数据表 | 用途 |
| --- | --- |
| `daily_market_review` | 每个交易日一条总体复盘；只保存原子指标 |
| `daily_price_limit_event` | 一只股票在一个交易日触及一个方向的涨跌停价时一条记录 |
| `daily_price_limit_event_detail` | 与一条触板事件一对一的可空明细 |
| `daily_price_limit_event_sector` | 事件的有序、多值所属板块 |
| `daily_price_limit_event_reason` | 事件的有序、多值涨停原因 |

`daily_price_limit_event` 使用 `(trade_date, market, code, direction)` 作为主键。涨跌停事实独立于总体复盘：删除 `daily_market_review` 不删除同日事件。三张明细表以外键级联到事件；删除事件时级联删除明细。

入库身份使用 `(market, code)`：`market` 为小写 `sh | sz | bj`，`code` 为保留前导零的 6 位字符串。不维护证券主表。

`daily_market_review` 只保存各指数收盘与前收盘、各市场融资余额和成交额等原子字段。有效涨停、炸板、连板汇总、合计和涨跌幅均不保存在该表中。

`is_leader` 在 SQLite 中用 `INTEGER` 的 `1` / `0` / `NULL` 存储；公共返回值转换为 Python `bool | None`。

## 4. 表结构

```sql
CREATE TABLE IF NOT EXISTS daily_market_review (
    trade_date TEXT NOT NULL PRIMARY KEY,
    pullback_count INTEGER,
    median_change_pct REAL,
    advancing_count INTEGER,
    declining_count INTEGER,
    margin_balance_sh REAL,
    margin_balance_sz REAL,
    margin_balance_bj REAL,
    sh_index_close REAL,
    sh_index_prev_close REAL,
    sz_index_close REAL,
    sz_index_prev_close REAL,
    cy_index_close REAL,
    cy_index_prev_close REAL,
    turnover_amount_sh REAL,
    turnover_amount_sz REAL,
    turnover_amount_cy REAL,
    turnover_amount_bj REAL,
    total_market_cap REAL,
    float_market_cap REAL,
    pe_sh REAL,
    pe_sz REAL,
    pe_cy REAL,
    pe_all REAL,
    avg_stock_price REAL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
) STRICT;

CREATE TABLE IF NOT EXISTS daily_price_limit_event (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    name TEXT NOT NULL,
    direction TEXT NOT NULL,
    closed_at_limit INTEGER NOT NULL,
    limit_rate_bp INTEGER NOT NULL,
    streak_height INTEGER NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction)
) STRICT;

CREATE TABLE IF NOT EXISTS daily_price_limit_event_detail (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    previous_turnover_amount REAL,
    auction_amount REAL,
    previous_close REAL,
    open_price REAL,
    turnover_amount REAL,
    turnover_rate REAL,
    is_leader INTEGER,
    note TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;

CREATE TABLE IF NOT EXISTS daily_price_limit_event_sector (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    position INTEGER NOT NULL,
    value TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction, position),
    UNIQUE (trade_date, market, code, direction, value),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;

CREATE TABLE IF NOT EXISTS daily_price_limit_event_reason (
    trade_date TEXT NOT NULL,
    market TEXT NOT NULL,
    code TEXT NOT NULL,
    direction TEXT NOT NULL,
    position INTEGER NOT NULL,
    value TEXT NOT NULL,
    PRIMARY KEY (trade_date, market, code, direction, position),
    UNIQUE (trade_date, market, code, direction, value),
    FOREIGN KEY (trade_date, market, code, direction)
        REFERENCES daily_price_limit_event (trade_date, market, code, direction)
        ON DELETE CASCADE
) STRICT;
```

多值表的 `position` 从 `0` 开始连续编号，保留输入顺序。不把外部来源序号直接入库。

## 5. 读写能力

数据层提供：

- 新增或 patch 指定交易日的总体复盘原子字段。
- 查询单个交易日或日期范围的原子字段。
- 删除指定交易日的总体复盘；涨跌停事件作为共享事实独立保留。
- 保存、更新和删除涨跌停事件；空事件列表为 no-op。
- 在同一事务中按旧方向删除并写入新方向事件（`replace_price_limit_event_direction`），同时迁移明细标量和 `sectors`；改为 `down` 时不迁移 `limit_up_reasons`。
- patch、查询事件明细及其多值板块、涨停原因；父事件不存在时整批失败。
- 读取事件与明细后生成单日梯队和炸板、跌停辅助名单。
- 组合查询单日的原子字段和事件；总体复盘或涨跌停事件任一存在即返回，二者都不存在才视为无数据。

批量写入使用普通事务，避免数据库故障造成半批写入，不代表数据库确认内容正确。

除原子方向替换接口外，不定义 `direction_replace`、`item_patch` 等额外操作模型。

## 6. 技术验收

1. schema 更新不得损坏已有用户数据。V1 数据库打开后自动增加 V2 三张扩展表，原事件与复盘行不变。
2. 测试覆盖新建数据库、仅含 V1 表的已有数据库，以及活动事务中 WAL / foreign keys 未能开启时拒绝初始化。
3. `daily_price_limit_event` 使用日期、市场、代码和方向作为唯一键；方向变更必须通过 `replace_price_limit_event_direction` 在同一事务中完成，不能只改 `direction`，也不能依赖非事务的先删后写。
4. 批量保存事件或明细时，任一条失败整批回滚。
5. 删除事件级联删除 detail、sector 和 reason。
6. 字段级 patch 正确区分未提交、`null`、`0` 和 `false`；多值列表区分未提交、非空替换和 `[]` 清空。
7. 父事件不存在时拒绝写入明细。
8. `get` 保持 V1 的 `review` / `events` / `summary` / `missing_fields`，并新增 `ladder`。
9. `2026-08-21` 已由仓库沪深交易日历确认为已收盘交易日，前一交易日固定为 `2026-08-20`。黄金 fixture 至少覆盖连续多个交易日的涨停、当日跌停、首板、连板、炸板、打开跌停、收盘跌停、用户提供高度和缺省计算高度，以及展示统计预期。梯队股票总数必须与同一 fixture 的有效涨停数一致。
10. 持久化验收覆盖新增、更新、查询、删除和数据库故障时不会留下半批数据；业务内容正确性由 Skill 和用户负责。
11. repository 不根据股票名称推断 ST，也不复核证券宇宙过滤结果。
