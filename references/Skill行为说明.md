# Skill 行为说明

本文档描述采集、请求范围、冲突处理和用户交互。字段名、单位、事件身份与 patch 语义见 `数据字段与口径.md`。证券宇宙、ST 排除和统计公式见 `资本市场复盘指标说明与统计口径.md`。查看已保存数据时不要加载本文档，按 `SKILL.md` 执行。

## 操作分流

默认意图与改判条件以 `SKILL.md`「请求分流」为准。本文档仅在**写入**路径加载。

- 先判定**操作意图**（只读 / 写入），再判定**字段范围**（完整复盘 / 点名类别或字段）。
- 「统计 / 汇总」且未限定字段 → 写入 + 完整复盘；「统计上涨和下跌家数」等点名 → 写入 + **仅点名范围**，不扩大到八类。
- 用户只要求查看已保存数据 → 调用 `get`，按 `SKILL.md` 展示；不加载本文档

写入和显示相互独立。目标交易日按 `SKILL.md` 的日期规则确定；CLI 写入路径会拒绝未收盘或非交易日。分流确定后，**不因读库失败改写请求范围**。

## 读库失败（写入路径）

CLI 返回 `DB_UNAVAILABLE`（或等价无法打开库）时：

1. 报告 **数据库状态 = 未知 / 不可用**，附带错误信息。
2. 不推断库内缺项或已有内容；不把失败当成「无复盘数据」。
3. 保持原请求范围，继续取数与核验。
4. 分别记录：**采集状态**（本轮已确认 / 未完成 / 冲突未决）与 **数据库状态**（可用且已写入 / 可用但未写入 / 未知不可用）。二者可同时成立，例如「本轮已核验指数，但库打不开」或「库有旧记录，本轮补采失败」。

## 写入流程

```text
确定请求范围
        ↓
若触发涨跌停采集（见「流程适用范围」）→ 走「涨跌停采集执行流程」
        ↓
其他范围内字段：图片 / 链接 / API / 用户文字
        ↓
按指标核验；失败则重试或换源（两融除外）
        ↓
确认交易日期、字段含义和单位
        ↓
按字段合同换算并构造 patch（涨跌停须先确定可信 streak_height）
        ↓
调用 scripts/cli.py 写入（涨跌停用 save-events）
        ↓
分开报告采集状态、保存结果与数据库状态；仅对未完成或写入失败项列清单
```

构造任何写入 payload 时遵循字段合同的 patch 语义，不要把未提交、`null`、`0` 和空列表混用。

**完整复盘硬门禁：** 完整复盘（或明确请求全部涨跌停）时，未对四类涨跌停分别给出**采集结果**（已核验 / 部分采集 / 已核验零事件 / 获取失败+依据）并另列**保存结果**之前，**不得结束首轮**。新闻或网页汇总数**不算**已处理明细。无需用户再次点名个股。点名子类不触发本硬门禁的「四类齐全」要求，见「流程适用范围」。

## 请求范围与取数模式

先确定范围，再只对范围内字段分配取数模式。范围外字段不取、不写。

- 完整复盘：例如「请整理今天的复盘数据」「统计今日大盘市场数据」「从这张图片提取复盘数据并保存」。
- 点名字段或类别：例如「补齐两融」「把上涨家数修正为 3210」。

范围内未指定来源时进入自动整理：对范围内字段尽力取得数据；**自动整理 = Agent 自主选择获取方式**（网页、API、截图、用户文字等），不等于字段合同中的「自动承诺」。只写入成功且校验通过的项，并一次性列出未取得项目。字段合同中标记为自动承诺的指数字段，只要落在范围内且未指定来源，就必须尝试。

指定数据或来源时，只用该来源处理点名范围。来源中没有出现的字段保持原值，不清空，也不另找来源填空。除非用户同时要求扩大范围或自动补齐。

混合请求先定范围，再按字段分配来源。例如「整理今天复盘，用这张图核对上涨家数」：范围是完整复盘；只有上涨家数走该截图，截图中其他可识别字段不接管；其余范围内字段走自动整理。

看不清、页面日期与复盘日期不一致、单位不明确、或同一字段多个指定来源冲突时，该字段不入库。多来源冲突时不得猜测；用户明确指定来源时以用户要求为准，否则一次性列出冲突项。

需要用户提供数据时，一次性给出带单位的 YAML 或表格模板，不逐项对话。用户可以跳过。**不得**在尚未完成本轮涨跌停采集（按适用范围）的取数 / 核验 / 换源之前，把「请用户提供涨跌停名单」当作默认结束路径。

## 自动整理承诺

当前明确自动承诺的只有三只指数日 K：

- 上证 `sh000001`（代码 `000001`）
- 深证成指 `sz399001`（代码 `399001`）
- 创业板指 `sz399006`（代码 `399006`）

分市场 PE 与指数同一套代码。可通过 `scripts/marketreview/sources/tencent.py` 取得当日收盘和前收盘，再经 `save-review` 写入。只提交成功取得且成对完整的指数点位。

融资余额按下节采集。其余字段由 Agent 通过网页、图片、API 或用户输入尽力取得，不承诺固定数据源。无法确认日期、股票身份、字段含义或单位时不写入。来源、URL、截图和采集方式不入库。

## 融资余额采集

仅在整理、补齐或写入融资余额（含完整复盘中的两融）时采集和保存；只查看已保存数据时，仅调用 `get`。

未指定来源时，默认访问[同花顺 A 股融资融券页](https://data.10jqka.com.cn/market/rzrq/)，读取「融资融券历史数据」中「本日融资余额」的上海、深圳、北京三列，不取融资融券余额或融资买入额。用户指定来源时优先采用该来源，按其实际标注的单位换算为元；同花顺三列单位为亿元，乘以 `1e8`。

单独补齐融资余额且未指定日期时，取当前表里交易日期最新的一行，按该行日期保存。指定日期时，只接受当前表中日期完全一致的一行。完整复盘以目标复盘日为准；页面最新交易日期与目标复盘日不一致时，本轮不写这三项并说明页面日期，不另写到其他日期。不自行计算 T-1，不翻页。

Agent 核对交易日期和三个市场余额齐全后直接调用 `save-review` 保存，不另等用户确认。合计仍派生、不入库。

### 两融失败结束条件（专属，不自行换源）

所用来源无法读取、三市缺一或日期不符时：

- **结束本项**：不写入这三项，直接说明问题；能读取页面时说明其交易日期。
- **不自行换源**、不拿其他日期代替、不填 `0`。
- 完整复盘中其他类别仍按各自规则继续；两融失败不等于整单结束。

## 涨跌停四类采集执行流程

目标：对**适用范围内**的非 ST 个股事件分别采集、核验，在写入前确定可信 `streak_height`，并尽量 `save-events`；**不是**比对新闻家数后结束。采集结果与保存结果分开报告。

### 流程适用范围

| 请求范围 | 采集范围 | 硬门禁 |
| --- | --- | --- |
| **完整复盘**，或明确请求「全部涨跌停 / 涨跌停名单 / 四类」 | **四类全部** | 四类均须给出采集结果 + 保存结果 |
| 点名**单一子类**（如「只补今日炸板」「补收盘跌停」） | **仅该类**；不扩大到另外三类 | 仅该类 |
| 点名**连板**或**每日梯队** | **有效涨停**（连板高度与梯队的必要依赖）；不强制炸板 / 跌停两类 | 仅有效涨停 |
| **修正单条事件**、补写已有事件的梯队扩展 / `save-event-details` | **不触发**本节全量或四类采集；只处理点名对象 | 无 |
| 点名「涨跌停」但未限定子类 | 按**四类全部**处理 | 同完整复盘涨跌停部分 |

点名范围与「仅处理点名」分流合同一致：**不得**因本节存在就把「只补炸板」扩成四类。

四类与落库字段对应（统一事件模型，不拆表）：

| 采集任务 | `direction` | `closed_at_limit` | 含义 |
| --- | --- | --- | --- |
| 有效涨停 | `up` | `true` | 收盘封住涨停 |
| 涨停炸板 | `up` | `false` | 盘中曾触涨停价，收盘未封住 |
| 收盘跌停 | `down` | `true` | 收盘封住跌停 |
| 打开跌停 | `down` | `false` | 盘中曾触跌停价，收盘未封住 |

同一来源可覆盖多类，但**不得**用「只拉了一次收盘涨停池」宣称四类均已处理。同股同方向先合并核验，再写入一条事件。

### 核心流程

```text
按适用范围确定本轮采集的类（完整四类或点名子集）
        ↓
各类分别获取明细名单
        ↓
逐股核验（日期、身份、触板方向、收盘是否封住、涨跌幅限制、非 ST）
        ↓
对拟写入事件确定可信 streak_height（写入前；见「连板高度」）
        ↓
仅将「触板事实 + 高度均已确认」的事件 save-events（可分批）
        ↓
检查名单覆盖 / 与汇总数差异（记录，不阻断已确认个股）
        ↓
需要时再写梯队扩展（仅关联已保存事件）
        ↓
get 回读；各类分别报告采集结果与保存结果
```

高度暂不能确认的个股继续核验或列入未完成，**不影响**其他已确认事件保存。

### ST 硬规则（采集义务，不是停采条件）

- 复盘涨跌停事件**一律非 ST**：按**目标交易日**状态排除 `ST` / `*ST` 等；默认证券宇宙为**沪深京**（见指标附录）。
- 过滤是写入前义务；**不得**因缺少完整 ST 名单而整批停采、停写，或要求用户补名单。
- 个别股票 ST 状态待核验 → 该股暂不写，**不影响**其他已确认非 ST 事件入库；在该类下注明「部分采集 / 个别待核 ST」。
- 不依赖股票名称字符串判断 ST；优先用来源按日状态字段或可核验状态接口。

### 已验证明细路径（同花顺 dataapi）

编写时（目标日示例 `20260909`）已实际验证下列接口可返回带代码的个股明细。`date` 必须为 `YYYYMMDD`。分页：`page` 从 1 起，`limit` 建议 50–100，直到取满 `data.page.total`。

基础 URL：`https://data.10jqka.com.cn/dataapi/limit_up/<pool>`

| 采集任务 | `<pool>` | 映射 | 备注 |
| --- | --- | --- | --- |
| 有效涨停 | `limit_up_pool` | `direction=up`, `closed_at_limit=true` | 可加 `filter=HS,GEM2STAR` 覆盖沪深（含创业板相关）；**北交所可能不在此 filter** → 京市缺省时标部分采集并换源补京 |
| 涨停炸板 | `open_limit_pool` | `direction=up`, `closed_at_limit=false` | 必须确认「曾触涨停且收盘未封」；该池即炸板候选 |
| 收盘跌停 | `lower_limit_pool` | `direction=down`, `closed_at_limit=true` | 核对涨跌幅是否达跌停限制 |
| 打开跌停 | （同花顺本路径未提供专用池） | `direction=down`, `closed_at_limit=false` | **不得跳过**；须换独立明细源或用收盘价/最低价/跌停价交叉验证「曾触跌停未封」；仍失败则该类标「获取失败」并写依据，**不阻断**其他三类已确认写入 |

字段映射（同花顺行 → 事件）：

- `code` → 6 位 `code`；`market_id`：`17`→`sh`，`33`→`sz`（若出现其他 market_id 或京市代码，按指标附录确认 `market`）
- `name` → `name`
- `limit_rate_bp`：按当日涨跌幅限制，`10%`→`1000`，`20%`→`2000`，北交所 `30%`→`3000`（可用涨跌幅或板块规则确认，勿凭名称猜测）
- `streak_height`：**写入前**必须已确定可信值（见「连板高度」）；有效涨停优先用来源连板字段（如 `high_days` / 板高），否则按指标附录区分「前日未涨停」与「前日记录缺失」；炸板与跌停写 `0`
- 请求头建议带常规浏览器 `User-Agent`，`Referer: https://data.10jqka.com.cn/`

**本轮验证义务：** 即使文档已写主源，仍须实际请求目标日接口并记录是否取到明细。主源失败（非 0 状态、空名单但汇总数非零、日期不符）→ 换独立明细源再试至少一次。东方财富 `push2ex` 涨停/炸板/跌停池等可作为候选备源，但**须本轮验证成功**后才可依赖；编写环境下该备源曾出现空数据，不得写进「已尝试明细」却未真正拿到个股。

### 个股可信 vs 名单完整

- **个股可信（可提交写入）**：代码、市场、方向、收盘是否封住、涨跌幅限制、目标日非 ST，以及 **`streak_height` 已按规则确定** → 才可 `save-events`。
- **名单完整**：汇总数与明细长度、多源家数一致，且覆盖约定市场（沪深京）→ 才可在说明中称该类「已核验（完整）」。
- 汇总数不一致：继续查明范围（是否含 ST/北交所/盘中快照）、时间与名单差异；**不能**一刀切阻止可信个股保存。高度或 ST 未决的个股继续核验；其余已确认的先写。

### 采集结果与保存结果（必须分开）

每类先给**采集结果**（与是否写入成功无关），再给**保存结果**。二者可组合，例如「已核验 + 写入失败」「部分采集 + 部分写入」。

**采集结果**（适用的每一类必须落入其一）：

| 采集结果 | 条件（不要求已写入） |
| --- | --- |
| 已核验 | 明细已取并核验，覆盖约定宇宙；候选个股触板事实均已确认（高度未决者单列，见下） |
| 部分采集 | 仅核验了可确认子集；ST 个别待核、缺北交所、高度个别未决、或与汇总仍有差 |
| 已核验零事件 | 收盘口径下确认该类无符合宇宙的触板事件 |
| 获取失败 | 主源+至少一备源仍无可用明细；写明 URL/接口、日期参数与失败响应要点 |

**保存结果**（适用的每一类另列）：

| 保存结果 | 条件 |
| --- | --- |
| 已写入 | 本轮候选均已 `save-events` 成功（零事件则为「无需写入」） |
| 部分写入 | 仅子集写入成功 |
| 写入失败 | 有已确认候选但 CLI/`DB_UNAVAILABLE` 等导致未落入库；**保留已确认候选**供下轮重试，不得改标为「获取失败」 |
| 无需写入 | 已核验零事件，或本轮无该类候选 |
| 未尝试写入 | 采集失败或尚无可信候选 |

新闻、Choice、连板网首页摘要、「约 / 超」家数**不是**明细源，不得当作任一类的完成依据。

### 连板高度（写入前确定）

`streak_height` 是字段合同必填项：**必须在 `save-events` 之前**为每条拟写入事件确定可信整数；禁止先写后再补高度，也禁止用临时 `0`/`1` 占位污染连板统计。

| 情形 | `streak_height` |
| --- | --- |
| 炸板、跌停方向 | `0` |
| 用户提供连板数 | 校验为非负整数后原样使用 |
| 有效涨停 + 来源给出可核验板高（如 `high_days`） | 采用该板高（仍须与连续性规则不明显矛盾） |
| 有效涨停 + 前日同股**已保存**有效涨停 | 前日高度 `+ 1` |
| 有效涨停 + 能**确认**前日同股未收盘涨停（如前日有效涨停名单已核验完整且不含该股，或独立行情证明未封涨停） | 首板 `1` |
| 有效涨停 + **前日记录缺失**或无法确认前日是否涨停 | **不得**填 `1`；该股高度未决，继续核验/换源，**不写入**该股；不影响其他高度已确认事件 |

「库内前日无该股记录」≠「前日未涨停」。只有在能肯定「前日未有效涨停」时才写首板；历史缺失只影响该股与连板率分母，不得停止其他已确认事件保存。

### 连板与梯队

- 连板 / 梯队随**已保存**的有效涨停及其 `streak_height` 派生；高度未写入的股票不进入梯队。
- 前日有效涨停分母缺失 → 只标记**连板率**缺失；**不得**停止今日已确认事件保存。
- 事件扩展只能关联已保存事件；`is_leader` 不因板高自动认定；派生汇总值不能独立入库。

### 禁止的结束方式

- 只比较东财/连板网/同花顺**汇总数**后列入「涨跌停未核实」
- 因 ST 名单不齐而整类不停也不写
- 因个别股票高度未决而整批不写已确认事件
- 把「核验成功但写入失败」标成「获取失败」
- 要求用户提供名单（在尚未完成本节重试/换源之前）
- 完整复盘（或四类全量）首轮：有已确认候选却未尝试 `save-events`，且未说明写入失败（四类均为已核验零事件或获取失败且有依据的除外）

## 指标核验、重试与换源

适用于范围内、未指定来源的自动整理字段（**两融除外**；**涨跌停优先走上一节**）。目标：该继续查的继续查；无法确认的不写；不以新闻模糊概数入库。

### 通用步骤

1. **取数**：取得带交易日期与单位的原始值或个股明细。
2. **核验**：核对页面/接口日期是否等于目标复盘日；字段含义与单位是否可换算；多源或汇总与明细是否一致。
3. **失败处理**：核验失败、空结果、盘中未收盘快照、或汇总与明细不一致 → **重试同一来源或换独立来源**（至少再尝试一种不同渠道或接口），然后再次核验。
4. **出口**（成功与失败分开；不要把成功项列入未完成）：
   - **成功**：已取得并核验通过 → 写入；该字段/类别记为已确认，**不**列入未完成项。
   - **失败结束**（满足其一即可结束该字段/类别，并列入未完成项）：
     - 两种及以上独立来源仍冲突且用户未指定采信哪一个 → 不写入，列出冲突；
     - 来源均无法在收盘口径下确认日期、身份、含义或单位 → 不写入，说明原因；
     - 用户指定来源且该来源失败 → 不另找来源填空（除非用户同时要求自动补齐）。

新闻、Choice 摘要、「约 / 超」类概数不得作为入库值；可在完成说明中标注为非技能口径参考，且**不能**用来宣称请求已完成。

### 其他类别（摘要）

| 类别 | 核验要点 | 失败结束 |
| --- | --- | --- |
| 指数（自动承诺） | 目标日 K 线成对收盘/前收；内置腾讯源优先 | 腾讯失败可换独立行情源；仍失败则该项未完成 |
| 市场宽度 | 证券宇宙与指标附录一致；上涨/下跌家数同源 | 多源冲突且无法锁定收盘口径 → 不写，列冲突 |
| 成交额 | 分市场口径；创业板已含在深圳中、不重复加总 | 单位或市场口径不明 → 不写 |
| 市值 / PE / 平均股价 | 日期与代码（PE 同对应指数代码）一致 | 无法确认则不写 |
| 两融 | 见「融资余额采集」 | 不自行换源 |

## 采集状态、数据库状态与未完成项

首轮回复必须同时包含：

1. **请求范围**与分流判定（操作意图 + 字段范围：只读 / 完整复盘 / 点名类别；涨跌停须写明本轮适用的类）。
2. **数据库状态**：可用（已读或已写） / 未知不可用。
3. **采集状态**与**保存结果**（分开，可组合）：
   - 涨跌停：对**本轮适用的每一类**分别报告采集结果（已核验 / 部分采集 / 已核验零事件 / 获取失败+依据）**以及**保存结果（已写入 / 部分写入 / 写入失败+保留候选 / 无需写入 / 未尝试写入）；不要合并成一句「涨跌停未核实」，也不要用「获取失败」掩盖写入失败。
   - 其他范围内类别：已确认并写入 / 已确认待写入（仅库失败时）/ 未采集 / 冲突未决 / 按专属规则结束（两融）。
4. **未完成项**：对照请求范围与八类复盘（或点名范围）逐项列出仍未完成者；避免漏列回头波、中位数、创业板成交额、平均股价等。**已核验并成功写入的项不要列入。**高度未决、写入失败保留的候选须列入。
5. **完成表述**：范围内仍有未完成项或库写入失败时，明确「未完成」，不得宣称整单完成；范围内均已核验写入成功时，可报告该范围已完成。
6. **落库证据**：完整复盘或点名涨跌停时，说明是否已调用 `save-events` 以及 `get` 回读的事件条数（按适用类或 direction+closed_at_limit）；写入失败时说明保留的候选数量。

涨跌停表述必须区分：

| 表述 | 含义 |
| --- | --- |
| 未采集 / 获取失败 | 本轮未取得该类可核验名单（须有尝试依据） |
| 部分采集 / 按方向未完整 | 只核验了可确认子集或部分方向；与是否已写入无关 |
| 已核验 + 写入失败 | 明细已确认但未落入库；保留候选，不得改口为获取失败 |
| 已核验零事件 | 本轮已按规则核验，确认该类无符合口径的触板事件 |
| 库内无事件 | 仅表示 `get` 读到 `events=[]`；只读路径不要说成已核验零 |
| 库内事件派生（完整性未知） | `events` 非空时的只读展示口径；含「库内该方向无事件 → 派生为 0」 |

## 写入后的说明

只报告本次实际写入的范围和未取得项。不要把范围外的空字段当成失败。新记录中跳过的原子字段保存为空值，不得使用 `0` 或前一交易日数据代替。
