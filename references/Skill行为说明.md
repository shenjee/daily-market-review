# Skill 行为说明

本文档描述采集、请求范围、冲突处理和用户交互。字段名、单位、事件身份与 patch 语义见 `数据字段与口径.md`。证券宇宙、ST 排除和统计公式见 `资本市场复盘指标说明与统计口径.md`。查看已保存数据时不要加载本文档，按 `SKILL.md` 执行。

## 操作分流

默认意图与改判条件以 `SKILL.md`「请求分流」为准。本文档仅在**写入**路径加载。

- 先判定**操作意图**（只读 / 写入），再判定**字段范围**（完整复盘 / 点名类别或字段）。
- 「统计 / 汇总」且未限定字段 → 写入 + 完整复盘；「统计上涨和下跌家数」等点名 → 写入 + **仅点名范围**，不扩大到八类。
- 用户只要求查看已保存数据 → 调用 `get`，按 `SKILL.md` 展示；不加载本文档

写入和显示相互独立。目标交易日按 `SKILL.md` 的日期规则确定；CLI 写入路径会拒绝未收盘或非交易日。分流确定后，**不因读库失败改写请求范围**。

## 读库失败（写入路径）

CLI 返回 `DB_UNAVAILABLE`（或等价无法打开库）时：

1. 报告 **数据库状态 = 未知 / 不可用**，附带错误信息。
2. 不推断库内缺项或已有内容；不把失败当成「无复盘数据」。
3. 保持原请求范围，继续取数与核验。
4. 分别记录：**采集状态**（本轮已确认 / 未完成 / 冲突未决）与 **数据库状态**（可用且已写入 / 可用但未写入 / 未知不可用）。二者可同时成立，例如「本轮已核验指数，但库打不开」或「库有旧记录，本轮补采失败」。

## 写入流程

```text
确定请求范围
        ↓
图片 / 链接 / API / 用户文字（仅范围内）
        ↓
提取候选数据
        ↓
按指标核验；失败则重试或换源（两融除外）
        ↓
确认交易日期、字段含义和单位
        ↓
按字段合同换算并构造 patch
        ↓
调用 scripts/cli.py 写入
        ↓
分开报告采集状态与数据库状态；仅对未完成或写入失败项列清单
```

构造任何写入 payload 时遵循字段合同的 patch 语义，不要把未提交、`null`、`0` 和空列表混用。

## 请求范围与取数模式

先确定范围，再只对范围内字段分配取数模式。范围外字段不取、不写。

- 完整复盘：例如「请整理今天的复盘数据」「统计今日大盘市场数据」「从这张图片提取复盘数据并保存」。
- 点名字段或类别：例如「补齐两融」「把上涨家数修正为 3210」。

范围内未指定来源时进入自动整理：对范围内字段尽力取得数据；**自动整理 = Agent 自主选择获取方式**（网页、API、截图、用户文字等），不等于字段合同中的「自动承诺」。只写入成功且校验通过的项，并一次性列出未取得项目。字段合同中标记为自动承诺的指数字段，只要落在范围内且未指定来源，就必须尝试。

指定数据或来源时，只用该来源处理点名范围。来源中没有出现的字段保持原值，不清空，也不另找来源填空。除非用户同时要求扩大范围或自动补齐。

混合请求先定范围，再按字段分配来源。例如「整理今天复盘，用这张图核对上涨家数」：范围是完整复盘；只有上涨家数走该截图，截图中其他可识别字段不接管；其余范围内字段走自动整理。

看不清、页面日期与复盘日期不一致、单位不明确、或同一字段多个指定来源冲突时，该字段不入库。多来源冲突时不得猜测；用户明确指定来源时以用户要求为准，否则一次性列出冲突项。

需要用户提供数据时，一次性给出带单位的 YAML 或表格模板，不逐项对话。用户可以跳过。**不得**在尚未按本节完成核验 / 重试 / 换源之前，把「请用户提供涨跌停名单」当作默认结束路径。

## 自动整理承诺

当前明确自动承诺的只有三只指数日 K：

- 上证 `sh000001`（代码 `000001`）
- 深证成指 `sz399001`（代码 `399001`）
- 创业板指 `sz399006`（代码 `399006`）

分市场 PE 与指数同一套代码。可通过 `scripts/marketreview/sources/tencent.py` 取得当日收盘和前收盘，再经 `save-review` 写入。只提交成功取得且成对完整的指数点位。

融资余额按下节采集。其余字段由 Agent 通过网页、图片、API 或用户输入尽力取得，不承诺固定数据源。无法确认日期、股票身份、字段含义或单位时不写入。来源、URL、截图和采集方式不入库。

## 融资余额采集

仅在整理、补齐或写入融资余额（含完整复盘中的两融）时采集和保存；只查看已保存数据时，仅调用 `get`。

未指定来源时，默认访问[同花顺 A 股融资融券页](https://data.10jqka.com.cn/market/rzrq/)，读取「融资融券历史数据」中「本日融资余额」的上海、深圳、北京三列，不取融资融券余额或融资买入额。用户指定来源时优先采用该来源，按其实际标注的单位换算为元；同花顺三列单位为亿元，乘以 `1e8`。

单独补齐融资余额且未指定日期时，取当前表里交易日期最新的一行，按该行日期保存。指定日期时，只接受当前表中日期完全一致的一行。完整复盘以目标复盘日为准；页面最新交易日期与目标复盘日不一致时，本轮不写这三项并说明页面日期，不另写到其他日期。不自行计算 T-1，不翻页。

Agent 核对交易日期和三个市场余额齐全后直接调用 `save-review` 保存，不另等用户确认。合计仍派生、不入库。

### 两融失败结束条件（专属，不自行换源）

所用来源无法读取、三市缺一或日期不符时：

- **结束本项**：不写入这三项，直接说明问题；能读取页面时说明其交易日期。
- **不自行换源**、不拿其他日期代替、不填 `0`。
- 完整复盘中其他类别仍按各自规则继续；两融失败不等于整单结束。

## 指标核验、重试与换源

适用于范围内、未指定来源的自动整理字段（**两融除外**，两融只走上一节）。目标：该继续查的继续查；无法确认的不写；不以新闻模糊概数入库。

### 通用步骤

1. **取数**：取得带交易日期与单位的原始值或个股明细（涨跌停必须是个股事件，不能只用汇总数）。
2. **核验**：核对页面/接口日期是否等于目标复盘日；字段含义与单位是否可换算；多源或汇总与明细是否一致。
3. **失败处理**：核验失败、空结果、盘中未收盘快照、或汇总与明细不一致 → **重试同一来源或换独立来源**（至少再尝试一种不同渠道或接口），然后再次核验。
4. **出口**（成功与失败分开；不要把成功项列入未完成）：
   - **成功**：已取得并核验通过 → 写入；该字段/类别记为已确认，**不**列入未完成项。
   - **失败结束**（满足其一即可结束该字段/类别，并列入未完成项）：
     - 两种及以上独立来源仍冲突且用户未指定采信哪一个 → 不写入，列出冲突；
     - 来源均无法在收盘口径下确认日期、身份、含义或单位 → 不写入，说明原因；
     - 用户指定来源且该来源失败 → 不另找来源填空（除非用户同时要求自动补齐）。

新闻、Choice 摘要、「约 / 超」类概数不得作为入库值；可在完成说明中标注为非技能口径参考，且**不能**用来宣称请求已完成。

### 涨跌停数据核对

写入涨跌停事件、连板或每日梯队前，按指标口径执行证券过滤，并读取指标附录中的 20%/30% 限制与连板连续性规则。

- 先明确统计范围是沪深，还是沪深京；正式口径包含北交所，北交所 30% 触板事件记录为 `limit_rate_bp=3000`。
- 不能只信任数据源的汇总数或单个涨跌停池。取得个股明细后，检查页面日期、收盘状态、市场和当日涨跌幅限制；有冲突时用收盘价、前收盘价和当日限价交叉验证。
- 如 API 同时返回汇总数和名单，必须校验汇总数与名单长度一致。不一致、返回盘中快照或名单为空时，本轮不将该方向当作完整名单入库，应重试或换独立来源。
- 新上市股票不因本地证券主表滞后而被静默丢弃；Agent 仍需确认其不是上市首日或当日无涨跌幅限制的股票。
- ST：须按目标交易日状态排除。一时拿不到完整 ST 名单时，应换源或缩小到可核验子集并在未完成项中说明「ST 过滤未完成」；**不要**把「ST 未齐」直接当成停止一切涨跌停采集的理由，也不要在未换源前要求用户贴名单。
- 汇总与名单不一致且换源后仍未解决 → 不标记该方向完整，不写入残缺名单冒充完整。
- 允许写入可核验子集或部分方向时：必须在采集状态写明「部分采集 / 按方向未完整」；对应方向列入未完成项。此后 `get` 的 `summary` 仅反映库内记录，展示时不得暗示全市场该方向已采全或已核验为空。

事件与梯队其他约束：

- 事件扩展只能关联已保存的涨跌停事件，不能脱离父事件单独创建。
- `streak_height`：用户给了连板数就采用；没给时按指标附录计算后写入。
- `is_leader` 是用户或来源给出的三态判断，不根据板高自动认定龙头。
- 派生汇总值不能独立入库；用户只提供汇总值时，提示需要个股触板事件。

### 其他类别（摘要）

| 类别 | 核验要点 | 失败结束 |
| --- | --- | --- |
| 指数（自动承诺） | 目标日 K 线成对收盘/前收；内置腾讯源优先 | 腾讯失败可换独立行情源；仍失败则该项未完成 |
| 市场宽度 | 证券宇宙与指标附录一致；上涨/下跌家数同源 | 多源冲突且无法锁定收盘口径 → 不写，列冲突 |
| 成交额 | 分市场口径；创业板已含在深圳中、不重复加总 | 单位或市场口径不明 → 不写 |
| 市值 / PE / 平均股价 | 日期与代码（PE 同对应指数代码）一致 | 无法确认则不写 |
| 两融 | 见「融资余额采集」 | 不自行换源 |

## 采集状态、数据库状态与未完成项

首轮回复必须同时包含：

1. **请求范围**与分流判定（操作意图 + 字段范围：只读 / 完整复盘 / 点名类别）。
2. **数据库状态**：可用（已读或已写） / 未知不可用。
3. **采集状态**（按范围内类别）：已确认并写入 / 已确认待写入（仅库失败时）/ 未采集 / 部分采集（含按方向未完整）/ 已核验零事件 / 冲突未决 / 按专属规则结束（两融）。
4. **未完成项**：对照请求范围与八类复盘（或点名范围）逐项列出仍未完成者；避免漏列回头波、中位数、创业板成交额、平均股价等。**已核验并成功写入的项不要列入。**
5. **完成表述**：范围内仍有未完成项或库写入失败时，明确「未完成」，不得宣称整单完成；范围内均已核验写入成功时，可报告该范围已完成。

涨跌停表述必须区分：

| 表述 | 含义 |
| --- | --- |
| 未采集 | 本轮未取得可核验名单 |
| 部分采集 / 按方向未完整 | 只写入了可核验子集或部分方向；库内 `summary` 不能当全市场结论 |
| 已核验零事件 | 本轮已按规则核验，确认无符合口径的触板事件 |
| 库内无事件 | 仅表示 `get` 读到 `events=[]`；只读路径不要说成已核验零 |
| 库内事件派生（完整性未知） | `events` 非空时的只读展示口径；含「库内该方向无事件 → 派生为 0」 |

## 写入后的说明

只报告本次实际写入的范围和未取得项。不要把范围外的空字段当成失败。新记录中跳过的原子字段保存为空值，不得使用 `0` 或前一交易日数据代替。
