# Skill 行为说明

本文档描述 `daily-market-review` Skill 的采集、校验、统计、展示和用户交互规则。数据库字段与保存语义见 `数据字段与口径.md`。

## 操作分流

写入和显示是两个独立操作：

- 用户要求整理、补充、提取或修正 → 调用 CLI 写入
- 用户只要求查看 → 调用 `get`，格式化展示

## 写入流程

```text
确定请求范围
        ↓
图片 / 链接 / API / 用户文字（仅范围内）
        ↓
提取候选数据
        ↓
确认交易日期、字段含义和单位
        ↓
执行市场规则和输入类型校验
        ↓
转换成复盘原子字段或涨跌停事件
        ↓
调用 scripts/cli.py 写入
```

## 自动整理承诺

当前明确自动承诺的只有三只指数日 K：

- 上证 `sh000001`（代码 `000001`）
- 深证成指 `sz399001`（代码 `399001`）
- 创业板指 `sz399006`（代码 `399006`）

分市场 PE 与指数同一套代码：上海 `000001`、深圳 `399001`、创业板 `399006`。

可通过 `scripts/marketreview/sources/tencent.py` 取得当日收盘和前收盘，再经 `save-review` 写入。

其余涨跌停、两融、市场宽度、成交额、市值、PE、平均股价等，由 Agent 通过网页、图片、API 或用户输入尽力取得；其中创业板相关字段仍按上述代码取数。

## 修订语义

**原子字段**

- 未提到的保持原值
- 具体值更新，包括 `0`
- 显式 `null` 清空

**涨跌停事件**

- 同一「日期 + 市场 + 代码 + 方向」覆盖原事件
- 空列表保存是 no-op，不代表清空
- 方向属于唯一键；方向变化时必须调用 `replace-direction`

**连板高度**

- 用户给了连板数就采用用户值
- 用户没给时，有效涨停根据前一交易日同股已保存事件计算
- 炸板和跌停写 `streak_height=0`

## 显示

1. 调用 `get` 读取 `review`、`events`、`summary`、`missing_fields`
2. 按八类表格格式化展示
3. 原子字段为 `null` 时留空
4. 显示时不自动取数、不修改数据库

## 不可独立入库的派生值

有效涨停数、炸板数、最高板、连板数、炸板率、涨跌停比等由 `summary` 统计，不能作为原子字段写入。

用户只提供汇总值而没有个股明细时，应提示需要个股触板事件。

## 交易日校验

- 目标日必须是已收盘交易日
- 非交易日：不落库，提示最近交易日
- 当日尚未收盘（A 股 15:00 边界）：拒绝正式记录
- 交易日判断使用 `assets/trading_calendar.json`

## 证券校验

股票代码和市场基础校验使用 `assets/securities_master.json`；交易日校验使用 `assets/trading_calendar.json`。写入路径在 `scripts/cli.py` 中执行上述校验，repository 只做结构性持久化。
