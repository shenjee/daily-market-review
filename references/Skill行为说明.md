# Skill 行为说明

本文档描述 `daily-market-review` Skill 的采集、校验、统计、展示和用户交互规则。数据库字段与保存语义见 `数据字段与口径.md`。

## 操作分流

写入和显示是两个独立操作：

- 用户要求整理、补充、提取或修正 → 调用 CLI 写入
- 用户只要求查看 → 调用 `get`，格式化展示

## 写入流程

```text
确定请求范围
        ↓
图片 / 链接 / API / 用户文字（仅范围内）
        ↓
提取候选数据
        ↓
确认交易日期、字段含义和单位
        ↓
执行市场规则和输入类型校验
        ↓
转换成复盘原子字段、涨跌停事件或事件扩展 patch
        ↓
调用 scripts/cli.py 写入
```

## 自动整理承诺

当前明确自动承诺的只有三只指数日 K：

- 上证 `sh000001`（代码 `000001`）
- 深证成指 `sz399001`（代码 `399001`）
- 创业板指 `sz399006`（代码 `399006`）

分市场 PE 与指数同一套代码：上海 `000001`、深圳 `399001`、创业板 `399006`。

可通过 `scripts/marketreview/sources/tencent.py` 取得当日收盘和前收盘，再经 `save-review` 写入。

其余涨跌停、两融、市场宽度、成交额、市值、PE、平均股价和每日梯队扩展信息等，由 Agent 通过网页、图片、API 或用户输入尽力取得；其中创业板相关字段仍按上述代码取数。

每日梯队不承诺固定数据源。Agent 可使用腾讯、东方财富、用户文字、截图、网页抓取或其他可用来源；无法确认日期、股票身份、字段含义或单位时不写入，多来源冲突时不猜测。来源、URL、截图和采集方式不入库。

## 修订语义

**原子字段**

- 未提到的保持原值
- 具体值更新，包括 `0`
- 显式 `null` 清空

**涨跌停事件**

- 同一「日期 + 市场 + 代码 + 方向」覆盖原事件
- 空列表保存是 no-op，不代表清空
- 方向属于唯一键；方向变化时必须调用 `replace-direction`

**连板高度**

- 用户给了连板数就采用用户值
- 用户没给时，有效涨停根据前一交易日同股已保存事件计算
- 炸板和跌停写 `streak_height=0`

**每日梯队扩展**

- 扩展信息只能关联已保存的涨跌停事件，不能脱离父事件单独创建
- 标量未提到时保持原值；具体值（包括 `0`、`false`）更新；显式 `null` 清空
- `sectors` 允许用于所有方向；`limit_up_reasons` 只允许 `direction=up`，跌停事件写入该字段时整批失败
- 方向由 `up` 替换为 `down` 时，迁移明细标量和 `sectors`，不迁移 `limit_up_reasons`
- `sectors` 和 `limit_up_reasons` 未提到时保持原列表；非空列表整体替换；`[]` 清空
- 多值项去除首尾空白，拒绝空字符串，完全重复值只保留第一次出现的位置
- `is_leader` 是用户或来源给出的三态判断，Skill 不根据板高自动认定龙头；展示时只有 `true` 显示「龙头」，`false` 和 `null` 均留空

## 显示

1. 调用 `get` 读取 `review`、`events`、`summary`、`missing_fields` 和 `ladder`
2. 按八类表格格式化展示；只看总体复盘时可忽略 `ladder`
3. 原子字段为 `null` 时留空
4. 显示时不自动取数、不修改数据库

`get` 始终返回 `ladder`：

- 有效涨停按实际 `streak_height` 从高到低动态分组，首板进入高度 `1` 分组
- 同高度按 `market + code` 稳定排序
- 板块和涨停原因按保存顺序以 ` / ` 连接
- 竞价占比和开盘涨幅读取时计算，输入缺失或分母为 `0` 时留空
- `is_leader=true` 显示「龙头」，`false` 和 `null` 均不显示文字
- 涨停炸板、打开跌停和收盘跌停在梯队之后作为独立名单展示
- 只读请求不联网补齐缺失扩展字段，也不追问用户

## 不可独立入库的派生值

有效涨停数、炸板数、最高板、连板数、炸板率、涨跌停比等由 `summary` 统计，不能作为原子字段写入。

每日梯队名单、每个高度的股票数、竞价占比和开盘涨幅也属于读取视图或派生值，不能作为重复原子数据入库。

用户只提供汇总值而没有个股明细时，应提示需要个股触板事件。

## 交易日校验

- 目标日必须是已收盘交易日
- 非交易日：不落库，提示最近交易日
- 当日尚未收盘（A 股 15:00 边界）：拒绝正式记录
- 交易日判断使用 `assets/trading_calendar.json`

## 证券校验

写入时只校验市场、代码格式、方向、涨跌幅限制和连板高度：`market` 为小写 `sh | sz | bj`，`code` 为 6 位 ASCII 数字，`direction` 为 `up | down`，`limit_rate_bp` 为 `1000 | 2000 | 3000`，`streak_height` 为非负整数。不维护证券主表，不因代码是否「认识」拒绝写入。交易日校验使用 `assets/trading_calendar.json`。写入路径在 `scripts/cli.py` 中执行上述校验，repository 只做结构性持久化。

V2 扩展字段还需校验：金额和换手率为有限非负数，价格为有限正数，`is_leader` 为布尔值或 `null`，备注为字符串或 `null`，多值字段为非空字符串数组。`limit_up_reasons` 只允许 `direction=up`。竞价占比和开盘涨幅不接受直接写入。
